Making a task fit

B2 told you how many runs you get. This is how to need fewer of them — four levers, and knowing which one a given problem calls for. One of them you have already built.

Why a long chat gets expensive

A conversation has no memory of its own. Every time you send a message, the whole conversation so far goes along with it — so message fifty costs far more than message five, even if you typed the same words.

The space it all has to fit in is the context window: up to a million tokens on the newest paid plans, 500,000 or 200,000 on others, with part of it always held back for Claude's reply. ¹

That third column is the one that catches people. As a conversation nears the window, Claude summarises the earlier messages so it can keep going — and Anthropic states it plainly: "Longer conversations that trigger automatic context management consume more of your usage limit." ¹ The tidying itself costs you.

This is also why a very long conversation starts feeling vaguer. It is not getting tired — earlier detail has been compressed into a summary, and summaries lose things. If a chat feels like it is forgetting, that is your signal, not your imagination.

The four levers

A

Split the job into smaller runs

Three jobs that each finish beat one that dies two-thirds through. Applies whenever the failure was ran out partway.

B

Start a fresh conversation

Free, instant, and the most under-used. The moment the topic changes, the old history is pure cost. Applies when a chat is long and has drifted.

C

Put the document into a Project

Files uploaded to a Project are cached: "Every time you reference that content, only new/uncached portions count against your limits." ² Applies to a document you keep coming back to.

D

Capture the process as a Skill

You already know this one. A Skill sits unread until its description matches — so instructions you would otherwise paste every single time cost almost nothing until the moment they are needed. ³ Applies to a process you keep re-explaining.

The distinction worth getting right

C is for a thing. D is for a way of doing things. A 40-page policy PDF you keep quoting is a document — Project. The five formatting rules you apply to every deck are a process — Skill. Reach for the wrong one and you will be pasting something into every chat again by next month.

Drillpick the lever

Five situations

Same four options every time, so nothing is given away by the shape of the answer. Decide before you click — a wrong guess here is cheap and teaches more than a careful re-read.

You've been in one chat for two hours and it's now about something else entirely.

B. Two hours of unrelated history is re-sent with every message and buys you nothing. Free to fix, takes one second, and almost nobody does it.

You paste the same brand guidelines into every deck request.

D. Guidelines you apply are a process, not a reference document — and a Skill fires on its own, so you stop remembering to paste them. If they were a long PDF you occasionally quote, C would be right instead.

You keep quoting the same 40-page policy PDF across many separate chats.

C. A document you return to, so Project caching is exactly the mechanism — after the first upload, referencing it costs almost nothing. Re-uploading it into fresh chats is the expensive version of the same habit.

A Cowork run died two-thirds of the way through when the session ran out.

A. The job is simply bigger than one session. Three runs that each finish and save their output beat one heroic run that loses everything — and this is what your B2 numbers are for: you know roughly how big a run you can afford.

Every single time, you re-explain the same five formatting rules.

D. "Every single time" is the tell for a Skill, every time. This is the same instinct as L01 — and it is worth noticing that the thing you built to save yourself re-explaining is also the thing that saves you tokens. Same mechanism, two payoffs.

Doone real fix

Apply one lever, today

Pick the job from B2 — the one you now know the price of — and choose the single lever most likely to shrink it. Then actually do it: start the Project, split the run, write the Skill.

One lever, not four. The point is to find out whether the next run costs measurably less, and you can only learn that if you changed one thing.

Then measure it. Run the job again and put the new numbers into B2's calculator. If the runs-per-week figure went up, you have just proved the lever works on your work rather than in principle — which is the only proof worth having.
